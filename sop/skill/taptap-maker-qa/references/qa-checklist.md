# TapTap Maker（UrhoX + Lua）发布前全量 QA 审查细则

本文件供 Phase 2 深度审查与 Phase 3 回归复测对照使用。

---

## 一、严重程度分级标准

| 级别 | 定义 | 典型示例 | 发布准入影响 |
|---|---|---|---|
| **P0 阻断** | 导致崩溃、白屏、主路径卡死、丢档/坏档、必现核心规则错乱、可稳定刷钱/刷奖励漏洞、官方校验报错、上传后必现 404 | Lua 运行期报错/空指针崩溃、结算卡死无出口、重开直接报错、资源路径大小写不匹配导致云端 404、缺 `.meta` 或 UUID 冲突、损坏 JSON、激励视频中途关闭仍发奖、负数购买刷货币 | **🔴 禁止发布**（必须清零） |
| **P1 严重** | 核心系统明显异常、重开状态残留、广告/SDK 异常分支卡死、严重内存/事件泄漏、核心 UI 遮挡/无法点击、残留作弊/调试后门 | `SubscribeToEvent`/`LuaTween` 未解绑导致重开后回调翻倍、切后台回来 `dt` 过大穿墙或计时归零、广告失败后按钮永久置灰、连点重复扣费/双倍领奖、GM/调试开关仍为 `true`、旧存档升级后字段为 `nil` 报错 | **🟡 带风险/强烈建议修复** |
| **P2 一般** | 边缘交互瑕疵、长文本截断、空状态提示不明确、轻度音画不同步、偶发冗余日志 | 长商品名/大数字溢出省略不当、高频音效未限流轻微爆音、弹窗打开动画未完点击无反馈、残留大量 `print` | 可结合发版节奏修复或记录暂缓 |
| **P3 建议** | 代码健壮性、包体瘦身与可维护性建议 | 未引用的孤立资源/孤立 `.meta`、可优化的频繁表创建或每帧查找节点 | 不阻断本次发布 |

## 二、TapTap Maker 8 大专项审查维度

### 维度 1：状态机、流程闭环与防卡死（`state_flow`）
- **完整闭环**：`启动/加载 → 主菜单 → 新手引导 → 核心局内 → 暂停/恢复 → 结算（胜/负/平） → 重开/下一关 → 返回主菜单`。
- **防 Softlock**：弹窗/遮罩关闭后输入锁定标志是否恢复；新手引导中误点非高亮区域或快速关闭弹窗是否卡死流程；加载/过渡动画期间再次触发切换是否导致双场景叠加或状态撕裂。
- **重开/切关洁净度**：重新开始一局或切换关卡时，上一局的实体节点、状态表、Buff、倒计时、分数、输入锁、协程/定时器是否彻底重置。

### 维度 2：Lua 核心玩法、物理与帧循环（`lua_gameplay`）
- **Lua 语言高危坑**：
  - 隐式全局变量污染（忘记写 `local`，多局或多实例互相覆盖）。
  - 冒号 `:` 与点号 `.` 混用导致 `self` 为 `nil` 或参数错位。
  - Lua 1-based 下标越界（误按 0 下标遍历或 `#t` 边界少算/多算 1）。
  - 表中存在 `nil` 空洞导致 `ipairs` 提前中断或 `#table` 长度失真。
  - 在 `pairs`/`ipairs` 遍历表时直接 `table.remove` 导致跳过元素（应倒序遍历或延迟删除）。
- **时间与帧率保护**：
  - `Update(dt)` 是否对 `dt` 做了上限钳制（如 `math.min(dt, 0.05)` 或 `0.1`），防止切后台回前台或设备卡顿瞬间引发穿墙、瞬移、倒计时直接归零或一次性跳过关键判定。
  - 移动、计时、动画是否错误依赖帧数而非 `dt`。
- **联机/服务端项目额外查（若适用）**：客户端与服务端协议字段一致性、断线重连后状态恢复、关键结算是否仅由客户端单方信任。

### 维度 3：数值、经济、随机与防刷漏洞（`economy_logic`）
- **数值安全**：除零、产生 `NaN`（`0/0` 或 `x ~= x`）与 `math.huge` 污染核心货币/血量/进度；浮点精度误差导致条件判断永不成立或 UI 出现 `12.000000000001`。
- **防刷与事务顺序**：
  - 扣除资源前必须校验 `amount > 0` 且余额足够；严禁先发道具再扣款或因异常中途跳过扣款。
  - 领取奖励、购买升级、结算发奖、广告翻倍是否具备幂等锁/冷却防连点，防止 1 秒连点两次领双倍。
  - 满级、满背包、库存为 0、到达上限时是否仍继续扣费或报错。
- **随机与经济可持续性**：抽卡/掉落权重和是否为 0 或越界、保底计数边界、配置表引用的道具/关卡/技能 ID 是否全部存在；不看广告的基础玩法路径是否存在资源死锁。

### 维度 4：存档持久化与老版本直升兼容（`save_persistence`）
- **老版本存档直升新版本专项核对（每次更新必给明确结论）**：
  - **版本号与逐级迁移链**：存档是否记录 `saveVersion`（或等价版本号）；当读取到无版本号的早期存档或 `version < currentVersion` 时，是否执行幂等的逐级迁移（如 `v1 -> v2 -> v3`），而不是静默重置或覆盖成新档。
  - **新增字段默认值补全**：新版本新增的任何字段（新货币、新解锁项、新子表、新设置）在老存档中为 `nil` 时，加载阶段是否全部深拷贝补齐默认值，杜绝 `save.newSystem.level` 触发 `attempt to index a nil value` 崩溃。
  - **字段改名 / 类型变化 / 结构重构回填**：旧字段改名（如 `gold -> coin`）、扁平改嵌套、数组改字典或数值改表结构时，是否把老玩家的已有进度、货币、解锁与广告/权益成果完整迁移到新字段。
  - **旧配置 ID 删改与上限调整容错**：老存档中保存的关卡 ID、道具 ID、角色/建筑 ID 在新版本被删除、重命名或下调上限时，读取后是否能安全映射、钳制或清理，不会导致任务链卡死、空表遍历报错或界面白屏。
  - **跨版本云存档与本地存档合并（若接入）**：云端旧档与本地新档（或本地旧档与云端新档）相遇时，是否先做版本迁移再比较进度，严禁直接用旧结构覆写或丢弃较新进度。
  - **隔离模拟老档验证**：若有 Git 历史，对比上一版本存档结构构造隔离的老版本测试存档 JSON 验证直升路径；**全程不得修改或清空开发者正式存档**。
- **异常与坏档容错**：首次进入无存档、存档 JSON 损坏/被截断/类型异常时，能否安全回退而非启动白屏崩溃。
- **落盘与一致性**：关键节点（通关、获得高价值资产、解锁、设置项变更）是否及时保存；删除/重置存档后内存缓存是否同步清空。

### 维度 5：UI.json、交互边界与多端适配（`ui_interaction`）
- **UI.json 健壮性**：JSON 语法合法、节点名称与 Lua 绑定路径一致、引用的图集/贴图/字体真实存在；未在无必要情况下破坏官方 UI 图层结构。
- **输入与弹窗**：弹窗背景遮罩是否拦截点击防止穿透到底层场景；快速连点、动画未结束时关闭、多弹窗叠加关闭顺序是否确定；长按期间切后台/失焦是否残留按住状态。
- **显示与适配**：大数字（百万/亿）、最长文案/昵称、空列表、未解锁、禁用与失败状态是否均有明确展示；窄屏/长屏/刘海屏与底部系统手势安全区是否避让；避免把未经设计的裸 emoji 直接当正式图标系统。

### 维度 6：资源引用、.meta/UUID 与生命周期泄漏（`assets_lifecycle`）
- **UrhoX `.meta` 与 UUID**：全部正式资源必须配齐有效 `.meta`、无损坏元数据、全项目无重复 UUID（缺失项统一用 `generate_resource_meta` 补齐，绝不手编）。
- **路径大小写严格一致**：Lua 代码与 `UI.json` 引用的每个目录段和文件名，必须与磁盘真实大小写 100% 一致（防止 Windows 预览正常、上传 Linux 运行环境后 404）。
- **生命周期泄漏**：场景销毁、切页或重开时，`SubscribeToEvent`、定时器、Update 回调、`LuaTween` 动画句柄、动态创建节点是否成对解绑/销毁，避免越玩越卡或同一事件触发 N 次。
- **音频合规**：静音/音量开关是否覆盖全部 BGM 与 SFX；切后台/恢复是否正确暂停和恢复音频；高频碰撞/点击音效是否有防爆音节流。

### 维度 7：广告与平台 SDK 回调边界（`ads_sdk`）
- **配置与文档前置**：涉及广告必须先核对 `maker://ads-integration-guide`、`engine-docs/recipes/sdk.md` 以及 `get_ad_config` 与本地 `.project/settings.json` 的 `@runtime.ad` 一致性（忽略 `synced_at`）；本地配置缺失时只报告缺口，不自动构建也不抄别的游戏配置。
- **激励视频与回调铁律**：
  - 使用 `sdk:ShowRewardVideoAd` 时，**仅当 `result.success == true` 且在本次有效请求上下文内**才发放一次奖励。
  - 必须显式覆盖全部异常分支：**广告不可用/未就绪、加载中重复点击、加载失败、用户中途取消/跳过、回调超时、重复回调、晚到回调、玩家已离开当前页面后回调到达**。
  - 取消不发奖，失败不扣除玩家原有收益/不让按钮永久置灰，重复回调绝不双倍发奖。
- **排行榜/登录/分享（若接入）**：离线、未授权、空榜单、长昵称与接口失败均能安全降级，不编造假排名。

### 维度 8：发布卫生与包体整洁（`release_hygiene`）
- 清理或严格门控调试/GM 面板、无限金币、一键通关/跳关快捷键、`DEBUG = true` 开关。
- 清理高频刷屏的 `print`（尤其是 `Update` 帧循环内 `print`）。
- 排查硬编码本地绝对路径（`C:\`、`E:\`）、测试内网地址（`127.0.0.1`/`localhost`）、占位文案（`TODO`/`测试文本`）与敏感密钥。
- 检查打包目录是否误混入源稿（`.psd`/`.zip`）、参考源码、未裁剪完整中文字体全集或临时测试报告。

## 三、6 级证据分级标准（严禁虚报）

| 证据标识 | 显示标签 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| `static_review` | 静态代码确认 | 代码逻辑、引用、状态分支存在明确缺陷或已按规范修正 | 实际引擎运行和画面一定正常 |
| `script_audit` | 静态脚本扫描 | 文件存在性、大小写、JSON/meta 语法、UUID 唯一性、关键字残留 | 运行期动态拼装路径或深层逻辑 |
| `lua_validate` | 官方 Lua 校验 | 通过 Maker 官方 `run-lua-validate` / `preview validate` 检查 | 真实交互体验、真机与平台能力 |
| `isolated_sim` | 隔离/模拟测试 | 指定输入与模拟回调下的状态流转与数值计算正确 | 真实广告播放、真实云存档、实际收入 |
| `local_preview` | Maker 本地预览 | 本地引擎下主流程启动、显示、基础交互与日志表现 | 真机触控、异形屏安全区、真实平台服务 |
| `real_device` | 真机与平台实测 | 对应真机与真实平台服务下的实际行为 | 所有机型 100% 一致 |
| `suspected` | 疑似风险（待确认） | 静态分析高度可疑但依赖运行态或真机环境确认 | 尚未实证复现 |
