# 小游戏新版本运营资料

根据用户的游戏与本次真实更新，交付可直接复制到运营后台的字段和可上传的图片文件。默认完成所有必填项，并生成有事实依据、对玩家有用的可选内容。具体字段、选项和素材规格见 [references/form-spec.md](references/form-spec.md)，开始任务时读取；用户提供的新表单要求优先。

## 收集与判断

- 优先使用本轮提供的更新说明、游戏截图、游戏名、Logo、素材文件及明确指定的项目。用户指定源码时只读核对本版本的实际变化；不把历史版本、规划和未完成内容写成已上线功能。不自行选定用户其他游戏作为目标。
- 信息缺失时集中询问：游戏名/类型、本次已完成更新、上线日期与时区、是否对外展示日期、立即或定时上架、预约自动下载是否适用，以及用于匹配画风的游戏素材。已有信息不重复问。可先完成不依赖回答的文案。
- 游戏类型决定用词：经营、休闲、解谜等小游戏不套用大型游戏的赛季、职业、DLC或角色宣传。字段标签必须从后台给定列表选取，最多3个；纯修复不硬凑“新玩法”。若没有任何标签符合事实，指出必填冲突并请用户确认平台可接受的标签，继续其余资料。
- 日期及开关属于用户决策。未知值写在独立的“待确认设置”清单，不能将截图里的示例日期或勾选状态当作用户选择。日期未知时不宣称资料已可提交；小游戏预约下载适用性未知时给出条件建议并等待确认。

## 编写资料

按后台顺序输出版本名、新版本卖点、新版本标签、新版本介绍、上线日期及展示开关、上架与预约设置、主视觉素材、版本内容。字段使用简体中文，短而具体，突出玩家能体验到的变化；不要夸大、虚构奖励、捏造活动期限或用未证实的“首创”“全新升级”等词撑场面。

每个文本限长字段按 Unicode 字符数核对，标点、空格、字母和数字均计数；为跨平台计数差异避免 emoji。超限先压缩，交付时在字段标签旁标注“实际字数/上限”，复制区只放正文。版本名要能区分本次更新，可以使用真实版本号搭配简短主题。

至少生成1个有实际内容的版本内容模块，其标题必填。默认提炼1–5条真实更新重点；每条重点标题必填，并生成不超过100字的可选描述。只有一项更新就写一项，不为凑数量重复。修复或优化版本也可以用“体验优化”等真实内容。没有更新事实时先收集，不能凭空写完成稿。

可选配图优先使用能证明新内容的真实截图；必要时生成符合游戏的宣传插图并标明“宣传插图”，不可冒充游戏实机画面。新版本视频只有在现有合适MP4或用户要求制作时加入，不默认扩展为视频制作任务。直播、预约礼包、历史版本在本次截图中无可见字段细节；仅在用户提供相应信息或新截图时处理，不编造表单规则和礼包。

## 制作主视觉

必须交付两张实际图片：新版本头图、搜索品牌专区图。参考 [references/form-spec.md](references/form-spec.md) 的尺寸和 [references/visual-brief.md](references/visual-brief.md) 的方法。先看游戏参考图，识别角色、场景、色彩、材质、视角及本次更新主题；后台表单截图只用于识别字段，不能用作游戏画风参考。

需要AI生图时使用当前环境可用的图像生成能力；Codex内优先内置 image_gen，并按可用的 imagegen skill 使用，不自行编写API客户端或索要密钥。调用前说明图像引用的角色、保留项和准确文案。缺少游戏参考且无法从指定项目提取时先向用户索取素材，继续完成文案，不用通用幻想图替代游戏风格。

两图共享视觉主题、真实品牌及本次卖点，但分别设计16:9和2.5:1布局，避免简单拉伸。宽图需重新安排标题和主体，保证角色、Logo、文字完整。不要凭空设计已有游戏Logo，已有Logo优先使用原件；文字少而准确，小尺寸也要清晰。

最终图片保存到任务的用户交付目录，使用含版本标识的名称；不能只交提示词、网页占位图或默认生成目录的路径。逐张查看成品，检查画风、主体身份、中文文字、更新真实性、裁切、尺寸及格式。生图工具无法直接满足尺寸时优先重新生成或扩图；仅做必要的等比尺寸适配，不拉伸。若工具不可用，明确两张图未完成，可交付文案和提示词，不宣称全部完成。

## 交付与完成检查

交付“可填写文案.md”、两张最终PNG/JPG，并在需要时附更新重点配图及“素材说明.md”（用途、实际尺寸、格式、素材来源、是否AI生成）。可另打包ZIP，保留单独图片供上传。交付文案按后台字段名排列，必填项单独标记，可选项说明已生成或省略的具体原因。

最终检查：必填文本无遗漏且限长合格；标签在列表内且1–3个；决策字段已确认或明确列为待确认；两张必填图片存在并已检查；重点数量不超过5且标题、描述符合限制；定时上架不得晚于版本上线时间。任何待确认或缺图都要列明，不把待确认占位内容称作可提交成品。

此Skill默认准备资料。填写后台、保存草稿、上传素材或提交审核属于后续动作，只有用户明确要求这些动作时才执行；不因生成文案自行发布。
