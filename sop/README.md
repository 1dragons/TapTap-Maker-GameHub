# TapTap Maker 小游戏开发 SOP

版本：1.0.0 · 2026-10-31 · 适用：独立开发者 + Codex + TapTap Maker

这套制作体系优先服务手机竖屏经营与模拟游戏。目标是让想法经过参考研究、原型、完整品质样板与试玩，再扩展成完整游戏。它不能保证流量，也不把功能完成等同于体验达标。

## 从这里开始

- 在 **GameHub 游戏总控台** 左侧点击「**SOP 中心**」，即可直接交互浏览完整 11 阶段流程、全文搜索手册、实时预览 5 款开源中文字体、查看资源样例并一键为游戏项目接入 SOP（无需外部命令或浏览器）。
- 了解 [总流程与阶段标准](docs/流程/总流程.md)。
- 正式 UI 按 [先生成整页设计图，再按图实现](docs/流程/UI设计稿到实现.md)执行，逐页保留版本与预览对照。
- 新项目、已有项目、换聊天继续工作：读 [项目接入与日常调用](docs/流程/项目接入.md)。
- 本机调用：`$taptap-maker-sop`。安装后如技能列表尚未刷新，在目标游戏项目中新建聊天；也可直接要求读取本目录的入口文档。
- 当前证据与缺口：[交付验证记录](docs/交付验证.md)。

## 一句话使用

新项目：使用 $taptap-maker-sop 为当前 Maker 项目接入 <SOP根目录>，保留已有文件与规则。我的想法是：……

继续项目：使用 $taptap-maker-sop，读取当前项目的设计与进度，继续下一项已授权工作。

专项任务：按本项目 SOP 设计并制作商店界面，先复用已确认的视觉方向，完成后进行本地预览与针对性检查。

## 你与 Codex 的分工

你确定期望体验与关键取舍，确认玩法方向、视觉与声音样板、发布候选。Codex 主动研究、提出有依据的设计、制作、预览、修订并记录证据。构建、上传必须另有明确同意，发布候选确认不等于上传授权。

## 目录

- `docs/流程`：阶段流程、接入方法、参考研究、玩法原型、品质样板、正式制作、验收、迭代。
- `docs/规范`：玩法经济、界面目录、美术、字体、声音、Maker 技术、参考案例拆解、广告与发布。
- `docs/模板`：可复制到游戏项目的制作文件，不要求全部采用。
- `library`：固定版本参考源码、字体文件、来源与授权清单。第三方源码仅研究，不执行脚本、不安装其技能。
- `samples/breakfast`：街角早餐店的生成任务与待办；本次用户选择延后生成，不包含生成成品。
- `skill/taptap-maker-sop`：本机安装用的技能源文件。
- `scripts`：项目接入、资源下载、导航索引与验证工具。
- `portal`：本地静态阅读入口，不连接 Maker、不保存项目进度、不发布网站。

## 维护

更新文档或资源清单后运行 `python scripts/build_portal.py` 同步导航页，再运行 `python scripts/validate.py`。索引工具使用当前环境已有的 markdown-it-py，依赖见 `scripts/requirements.txt`；离线阅读页面不需要安装任何依赖。资源仅在明确需要更新时运行 `python scripts/download_library.py`，它复用已有下载与锁定版本，不自动跟随上游最新版本。

需要 HTTP 预览时运行 `python scripts/preview.py`，然后访问它输出的本机地址；按 Ctrl+C 停止。默认仅绑定 127.0.0.1，不发布到外网。启动器使用自动分配端口，避免占用已有服务。

已接入游戏保存自己的 SOP 版本和设计决定。中央文档更新不代表项目自动迁移，迁移需先评估受影响内容。
