# 项目接入与日常调用

## 首次接入

在 Codex 中打开目标游戏目录，用 `$taptap-maker-sop` 并说明是新项目还是已有项目。Skill 先检查 SOP 路径，再读当前游戏的 AGENTS.md、设计与进度，禁止覆盖已有内容。

可使用内置工具：`python <SOP根目录>/scripts/connect_project.py --project "<游戏项目绝对路径>" --mode existing`。新项目将 mode 改为 new。工具仅新增 `.sop` 文件和带边界标记的 AGENTS.md 入口，不调用 Maker、不改正式存档、不清理工作区。路径由你或当前工作区明确指定，不能猜游戏目录。

首次接入后生成 `.sop/project.json`、`.sop/进度.md`、`.sop/设计决定.md` 与 `.sop/验收.md`。配置记录 SOP 根目录、采用版本和新旧项目模式。目录存在时先检查，不覆盖记录；重复运行应无变化。

已有项目先列出：实际核心循环、已上线或未上线、现有页面与资源、存档与平台接入、最影响体验的问题。优先修一个体验闭环，不把已有实现直接判定为过时。

## 启动一次工作

1. 读取游戏 AGENTS.md、SOP 配置、进度、有关设计决定。
2. 检查实际代码与资源，确定这次需求是否仍与记录一致。
3. 按任务读取最少必要规范：界面、美术、声音、玩法、技术或发布。
4. 说明本次目标与验收方式，制作并预览；需要用户决定时给具体结果与取舍。
5. 更新进度、实际证据和剩余问题；重要设计决定记录理由，不复制全部聊天。

## 路由表

| 用户请求 | 必读 | 交付 |
|---|---|---|
| 新游戏想法 | 总流程、立项、玩法经济 | 立项判断、研究、原型计划与实现 |
| 接入已有项目 | 本文、制作验收、相关专业规范 | 现状评估、保留清单、下一项改进 |
| 做一个页面 | 界面交互、字体、已有风格 | 页面设计、所有适用状态、预览证据 |
| 生成图片或调整画风 | 美术资源、项目风格、字体约束 | 样张、生成记录、一致性检查 |
| 配音乐音效 | 声音、已确认声音目标 | 情绪与事件表、试听、音量与循环检查 |
| 调经济或广告 | 玩法经济、广告与当前引擎广告指南 | 产消与奖励测算、接入和真实验证缺口 |
| 修小问题 | 当前进度、对应规范 | 定位、修复、针对性检查 |
| 发布 | 发布规范、制作验收 | 候选结果、授权与证据清单 |

## 迁移与异常

- SOP 路径不存在：报告具体缺失路径，停止 SOP 接入和宣称遵循流程；用户可指定新路径。不要默默采用另一套模板。
- 中央 SOP 版本变化：报告当前项目采用版本及受影响差异，经讨论后记录迁移；不自动覆盖设计。
- 尚未确认方向：继续独立研究或整理，但不把未确认方案批量实现。
- 字体、素材授权或设备效果未查清：把该项列为待确认，不写已通过。
- 工具调用状态不明：先查任务状态和已有结果，避免重复付费生成或重复上传。
