# 项目接入与日常调用

## 1. 首次接入（两种方式任选）

- **方式一（推荐 · GameHub 一键接入）**：在 **GameHub 游戏总控台** 左侧「SOP 中心」选择目标游戏项目，点击「一键接入 SOP」（自动区分新项目 `new` / 已有项目 `existing`）。
- **方式二（命令行 / Skill 接入）**：在任意 AI 编程助手（Antigravity / Codex / Cursor 等）打开目标游戏目录，调用 `$taptap-maker-sop` 或运行：
  ```bash
  python <SOP根目录>/scripts/connect_project.py --project "<游戏项目绝对路径>" --mode existing
  ```
  新项目将 `--mode` 改为 `new`。工具仅新增 `.sop/` 记录文件与带边界标记的 `AGENTS.md` 入口，**不调用 Maker、不修改正式存档、不清理未提交工作**。

首次接入生成 `.sop/project.json`、`.sop/进度.md`、`.sop/设计决定.md`、`.sop/验收.md`。已存在时重复运行保持无变化，绝不覆盖历史记录。

### 推荐仓库 `.gitignore` 规则（接入时顺手检查）
为防止非运行时产物污染游戏包体或造成构建状态误判，建议在游戏项目根目录 `.gitignore` 中排除：
- 临时报告与过程文档：`*.html`（QA/诊断/审阅看板）、`qa-reports/`、`diagnosis-reports/`、`acceptance/`、`素材备份/`
- 本地测试存档与临时输出：`save.json*`、`.tmp/`、`*.log`

## 2. 已有项目现状评估

已有项目接入时，先用只读方式快速盘清 5 件事，不把成熟实现粗暴推翻重做：
1. 当前核心循环、2D/3D 与横竖屏形态、是否已上线（公测 / 正式）；
2. 版本号三处状态（脚本常量 / Maker 配置 / Git 最新提交）；
3. 现有存档版本（`saveVersion`）与云存档/排行榜/广告/埋点接入现状；
4. 最影响玩家体验或线上口碑的 P0/P1 痛点（可结合 GameHub TapTap 评价雷达查看）；
5. 确定当前直接落位的阶段（通常是「分批正式制作」「发布前全量 QA」或「双驱迭代」）。

## 3. 日常按需路由表（不机械重跑全流程）

| 你的当前诉求 | 优先工具 / 技能 | 必读 SOP 文档 | 预期交付 |
| :--- | :--- | :--- | :--- |
| 新游戏立项与核心原型 | `taptap-maker-sop` | 总流程、立项与参考研究、玩法与经济 | 定位判断、最小原型、3D 平面动线图 |
| 定视觉/空间基线或做 UI | `taptap-maker-sop` | UI 视觉基线与实现、界面与交互、字体与排版 | A 类基线与 Design Token / B 类直出与多比例截屏 |
| 做美术、3D 场景或音效 | `taptap-maker-sop` | 美术与资源、音乐与音效、Maker 开发 | 风格锚点样张、动线防卡死检查、混音与广告后恢复验证 |
| 写核心功能 / 存档 / 排行榜 | `taptap-maker-sop` | Maker 开发、存档与风控 | 生产避坑落地、老档迁移链、防刷校验与 LSP 清零 |
| 调经济数值或接广告变现 | `taptap-maker-sop` | 玩法与经济、广告与商业化 + 当前广告指南 | OPT 入口方案、口碑红线核对、漏斗埋点 |
| **准备构建上传前体检** | **`taptap-maker-qa`** | 正式制作与发布前 QA、存档与风控 | 自动扫描+8 维审查+全修回归+HTML 验收看板 |
| **准备新版本商店宣传资料** | **`mini-game-version-ops`** | 发布与运营 | 限长可填文案 + 16:9 头图与 2.5:1 品牌专区图 |
| **分析线上留存/漏斗/广告** | **`game-diagnosis`** | 数据与玩家双驱迭代 | GamePropel 只读分析 + ≤3 个优化点 HTML 诊断看板 |
| **看玩家评价与论坛 Bug** | **`GameHub` 评价雷达** | 数据与玩家双驱迭代 | 全量/增量拉取 + 本地分类 + AI 诊断 + 一键转待办 |

## 4. 迁移与异常约定

- **SOP 路径缺失**：明确报告缺失路径并停止宣称遵循 SOP，不私自套用不明模板。
- **中央 SOP 升版（如 v1.0 → v2.0）**：不自动覆写旧项目已有设计与进度；先评估受影响项（重点补齐生产避坑、老档迁移与 QA 闭环），经讨论后再更新项目记录。
- **换聊天续接工作**：优先在 GameHub 点击 **「复制 AI 上下文」**，直接携带路径、版本、提交、待办和随手记秒级续接。
