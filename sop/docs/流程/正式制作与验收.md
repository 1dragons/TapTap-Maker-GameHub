# 正式制作与发布前 QA 闭环

## 1. 分批制作原则

以**可玩体验闭环**划分开发批次（例如“接单 → 执行 → 结算 → 升级”或“核心玩法 + 对应音效与飘字反馈”），不把代码、美术、音频切成互相脱节的大批次。每批开发遵循以下纪律：

1. **改前先读代码真相**：先检查现有模块、公共组件、存档结构与事件调用链，只做最小必要改动；禁止顺手重命名稳定字段或大面积重写无关文件。
2. **工程防线前置落地**：开发期直接遵守 [Maker 开发规范](../规范/Maker开发.md)（`dt` 钳制、广告后音频重建、多指触控隔离、LSP 0 警告）与 [存档与风控规范](../规范/存档与风控.md)（`saveVersion` 迁移、防刷校验、发版开关收敛）。
3. **资源入库即清洁**：新图片/模型/音频入库前核对尺寸、透明边缘、命名、路径大小写与官方 `generate_resource_meta` 生成的 `.meta`；及时清理废弃模型与孤立 `.meta`。
4. **每批轻量验证**：完成后运行本地预览，按改动影响范围做针对性检查，不因为改一行文案去重跑全量回归。

## 2. 改动与回归范围表

| 改动类型 | 必要检查 | 扩大检查的触发条件 |
| :--- | :--- | :--- |
| 文案、字号、单一布局调整 | 对应页面长文本、4:3 与长屏适配、防重叠 | 修改公共 HUD / 通用弹窗组件 |
| 美术、3D 模型或音频替换 | 引擎加载、阴影/透视/透明边缘、循环与音量 | 出现帧率下滑、内存上升或全局音频异常 |
| 单个玩法或触发器修复 | 复现路径、相邻触发优先级、防卡死边界 | 改动共享状态机、结算、主循环 `dt` 或存档 |
| 经济、广告或埋点调整 | 产消平衡、奖励单次发放、失败/取消不卡死、漏斗上报 | 涉及跨阶段成长、云端 `@runtime.ad` 对齐或老档兼容 |
| 存档结构、排行榜或公共框架 | 隔离老档直升测试、坏档兜底、风控边界 | 出现字段 `nil`、迁移失败或数值异常 |
| **准备构建上传（发布候选）** | **完整执行 `taptap-maker-qa` 全量体检与自动修复闭环** | 候选确认后若再次改代码，必须补跑受影响回归 |

## 3. 发布前全量 QA（正式衔接 `taptap-maker-qa`）

每次准备构建上传前，不再依赖零散手工翻查，统一触发 **`taptap-maker-qa`** 执行一站式闭环：

1. **自动化静态预检 + 官方 Lua 校验**：扫描配置健康度、缺失/孤立 `.meta`、重复 UUID、跨平台路径大小写 404、调试/修改器残留、事件/Tween 泄漏，并执行当前发行版 `run-lua-validate` / `preview validate`。
2. **云端配置与线上日志核对（按需）**：
   - 含广告项目：核对云端 `get_ad_config` 与本地 `.project/settings.json` 的 `@runtime.ad` 一致性；
   - 线上迭代版本：只读拉取 `get_debug_feedbacks` 真实报错日志，并基于 `git diff` 强制产出 **「老版本存档直升兼容性结论」**。
3. **8 大维度全量审查与自动修复回归**：按 `P0 → P1 → P2 → P3` 一次性修完所有可自动修复项并复测归零（生产 LSP 0 警告、所有调试/诊断开关关闭）。
4. **可视化 HTML 看板交付**：报告输出到项目外安全归档目录（**严禁污染游戏包体**），首行明确给出 **`是否建议构建上传：是 / 否`** 与老档直升结论，由用户审阅后决定是否授权构建上传。

## 4. 6 级证据铁律

严禁把低级别验证写成高级别通过，所有验收记录必须明确标出证据级别：

| 证据级别 | 能证明什么 | 不能证明什么 |
| :--- | :--- | :--- |
| 1. 静态检查 / 脚本扫描 | 语法、引用、`.meta`、配置与开关无明显隐患 | 实际运行、画面与逻辑一定正确 |
| 2. 隔离模拟测试 | 指定输入、老档迁移与模拟回调的状态机逻辑 | 真广告、真云端、真实收入 |
| 3. 资源级预览 / 试听 | 单张图外观或单条音频可播 | 引擎渲染、遮挡阴影、局内混音 |
| 4. 官方 Lua 校验 | 通过 Maker 当前版本静态/运行时校验 | 真机触控手感、多比例 HUD 观感 |
| 5. Maker 本地预览 | 本地引擎下主循环、UI 交互与视听表现 | 真机刘海安全区、真实广告、真实云存档 |
| 6. 真实设备与平台 | 对应设备与线上服务的真实结果 | 覆盖所有未测机型与全量玩家表现 |

## 5. 仓库与包体清洁检查

构建上传前核对项目 `.gitignore`，确保非运行时产物不被打包或干扰版本追踪：
- QA / 诊断 HTML 与 JSON 报告、验收视频、设计原稿与素材备份、`docs/` 与 `.sop/` 过程文档、本地测试 `save.json` 均不混入游戏运行时资源目录。
- 核对 **三处版本号一致**：脚本版本常量（如 `GAME_VERSION`）、Maker 工程配置版本、最新发版 Git 提交/标签。
