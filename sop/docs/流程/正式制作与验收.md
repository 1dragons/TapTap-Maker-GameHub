# 正式制作与验收

## 分批制作

以可玩体验闭环划分任务，例如“接单至结算”，不要只按代码、美术、音频分成互相脱节的大批次。每批写明目标、涉及页面与资源、边界、完成标准、受影响系统。

先查已有组件与数据，再实现最少必要改动。接入新资源时检查许可证、文件尺寸、命名、透明边缘、字体与声音。每批完成后运行实际预览，对照已确认样板检查。

## 改动与检查范围

| 改动 | 必要检查 | 扩大检查的触发条件 |
|---|---|---|
| 文案、字号、按钮位置 | 对应页面与长文本、小屏状态 | 影响公共组件或布局规则 |
| 图片、声音替换 | 实际显示或播放、格式、体积与资源引用 | 加载异常、内存压力或全局音频行为改变 |
| 单一玩法修复 | 复现问题、修后路径与邻近边界 | 修改共享状态、计时、结算或存档 |
| 经济与广告 | 受影响产消、奖励与异常回调 | 跨成长阶段、存档迁移或核心付费经济 |
| 公共框架或存档 | 主要路径与旧数据兼容 | 出现新的失败与不一致 |
| 发布候选 | 完整首局、主要成长、退出恢复、平台能力与性能 | 候选后继续发生相关修改 |

不为低影响可逆改动编写只复述实现的测试。不做常规文件哈希验证；正式存档保护优先使用隔离测试目录和受控测试存档。

## 证据分级

| 证据 | 能说明什么 | 不能说明什么 |
|---|---|---|
| 静态检查 | 文件、引用、逻辑与规则符合检查项 | 实际显示和运行一定正确 |
| 隔离或模拟测试 | 指定输入和模拟回调的行为 | 真广告、真云端、实际收入 |
| 资源级预览或试听 | 图像外观、声音文件播放 | 引擎兼容、游戏内混音、无缝循环 |
| Maker 本地预览 | 本地引擎的指定流程表现 | 真机触控、安全区、真实平台服务 |
| 远程构建成功 | 构建流程成功 | 玩家设备、广告收入或平台批准 |
| 真实设备与平台 | 对应设备和服务的实际结果 | 所有设备都一致 |

每项记录环境、步骤、结果、证据位置和剩余风险。使用“通过、部分通过、失败、未运行、不适用”，部分通过必须写明缺口。

## 发布候选

检查启动与加载、首局、核心成长路径、资源产消、失败与重试、设置持久化、存档恢复、暂停与返回、长时间操作风险、广告与排行等适用能力。设备和平台项不能用模拟结果勾选通过。

缺陷按影响排序：无法进入或存档损坏优先；阻断主要路径其次；视觉与表现问题再结合用户体验处理。剩余风险要具体到行为和范围。用户确认候选后仍需明确构建上传授权。
