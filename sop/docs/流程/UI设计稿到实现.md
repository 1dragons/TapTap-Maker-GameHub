# UI 先出图，再按图实现

这是用户指定的正式 UI 制作方式：先用 Codex 可用的图像生成能力制作完整页面设计图，确定满意的版本，再以选定图片为视觉基准在 Maker 中还原。每个正式页面先有设计稿；已确定页面的小修可修改现有稿和实现，保留新版本记录。

## 1. 确定画面需求

先填写[单界面设计表](../模板/单界面设计表.md)，确定页面目的、信息顺序、真实文案、典型数据、主要动作、必要状态、设计分辨率和安全区。准备项目参考板、已选字体与字重、场景和角色参考。同一项目的后续页面引用已确认设计图，保持组件、颜色和排版一致。

## 2. 生成整页视觉设计图

实际调用图像生成工具，先完成最能表达风格的主页面，再按确认方向逐页生成主菜单、局内 HUD、管理、商店、结算、设置等项目实际需要的页面。先集中探索主页面的候选方向，避免风格未定就批量生成全套。

设计图必须展示完整构图、背景、主辅色、按钮、卡片、图标、装饰和文字层级，图片干净、无任何噪点。它是完整视觉设计稿，可包含用于说明布局的文字；中文误字、字体不准或缺字要标记并用真实字体校正后展示。正式实现的中文、数字、按钮标签和动态内容使用实际字体与 UI 组件。

每一轮修改保存独立版本，记录提示词、参考图、输出文件、设计尺寸、修改内容与选用状态。页面名和版本可用 `shop-v01`、`shop-v02`，不覆盖用户已选定的稿。空、失败、禁用等关键状态提供附图或明确标注；涉及布局变化时补对应状态稿。

## 3. 选定基准，提取实现规格

用户选定的风格样板及其页面版本作为实现基准，纳入原有“视觉与声音样板确认”节点。同方向的后续页面按已确认规则分批交付；重大风格或布局变化先展示修订图。不要在实现阶段凭感觉改掉选定设计。

从选定图片提取并记录：背景/主辅色/文字/边框的色值，字体与字重，字号与行距，元素位置与尺寸，内外间距，圆角、边框、阴影，图标大小，图片裁切与层级。生成图本身没有可靠的字体和颜色源数据，提取结果需校正并固定为项目设计参数；之后复用这些参数，避免每页重新猜测。

区分可复用 UI 组件和独立美术资产。按钮、列表、文本、进度条与动态数值采用真实组件；场景、插画、独特装饰等按需切图或单独生成。已有清晰图像资产能复用时优先复用。具体切图、元数据和 UI.json 实现先读当前 Maker UI 工作流。

## 4. 按图还原并对照修订

在设计稿对应的基准分辨率下，以 1:1 视觉还原为目标，逐项落实背景颜色、位置、比例、间距、字体、按钮和装饰。保持设计稿与实际预览使用相同页面状态、文案、数据和截图区域，制作并排对照，必要时叠加对照，记录明显差异并修正。

差异检查按构图和层级→背景及配色→组件尺寸与间距→字体字重与换行→图标和装饰的顺序处理。字体、抗锯齿、实时渲染效果可能与生成图不同；不能通过缩小文字或牺牲操作来掩盖差异。必要调整记录原因与更新后的基准图，影响已确认风格时交由用户确认。

基准画面还原后再检查窄屏、长屏和安全区，按锚点、伸缩和滚动规则适配。不同屏幕保持视觉关系与操作可用，不把整张 UI 图等比缩小充当实际界面。检查按钮可点、内容可变、状态可切换和返回路径，并区分设计图检查、Maker 本地预览与真机结果。

交付：选定设计图及版本、实现规格、必要切图/组件、实际预览截图、并排对照与剩余差异。没有实际游戏项目时只完成规范或明确的设计任务，不初始化本 SOP 资料库；已延后的早餐店样例保持待办。
