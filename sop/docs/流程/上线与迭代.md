# 上线观察与迭代

输入是平台数据、真实玩家反馈和版本范围。先记录指标定义、时间窗口、样本量与来源，再判断问题。

| 环节 | 观察 | 优先排查 |
|---|---|---|
| 曝光 | 被多少目标玩家看到 | 平台分发、渠道、题材与更新窗口 |
| 点击 | 曝光后是否进入 | 图标、名称、截图、介绍是否传达真实吸引点 |
| 启动 | 点击后是否成功进入 | 包体、加载、兼容性、错误 |
| 首局 | 是否理解并完成第一次循环 | 教学、界面、操作、等待与反馈 |
| 留存 | 相同口径玩家是否回来 | 核心乐趣、目标、变化、存档和打断 |
| 广告 | 入口触达、请求、展示、完成 | 奖励价值、入口时机、SDK与广告供应 |
| 收入 | 平台结算的真实收入与口径 | 广告完成、展示、eCPM和地区等因素 |

曝光少不能直接证明玩法差；点击低不能直接靠加系统解决；模拟广告不代表广告收入。不要把商店漏斗与局内广告漏斗合成一个指标。

一次迭代写清问题、证据、原因假设、修改内容、期待变化、验证窗口与停止条件。样本少时报告不确定性，不强行归因。优先改一个主要问题，保留版本与口径，避免多个大改后无法判断效果。

发布记录包含已授权动作、构建结果、审核情况、已知问题、回退或修复方案。回退是否涉及存档兼容需先确认，不通过清除玩家存档实现回退。
