# 可选广告与商业化

游戏可以无广告。决定采用时，先明确入口目的和玩家收益，不把广告当作弥补核心体验不足的工具。

## 入口设计

每个入口填写：触发情景、玩家困难、正常玩法路径、奖励、使用频率、经济影响、失败与取消行为。例如临时应急、阶段效率或失败后的合理补救应有不同作用，避免多个入口只是重复发同一种钱。

入口明确说明观看与收益，不伪装普通操作、不在误触区域突然出现。基础领取、继续与广告奖励有清晰区别。关键操作与首轮体验避免被不必要打断。

## 奖励平衡

测算奖励折合正常玩法的产出或时间，检查早中后期差异、叠加、重复领奖、囤积与无广告路径。可以采取阶段适配、次数限制或递减，但必须对应体验目标，不能随意堆限制。

复活不能让主要失败成本完全消失；加速不能永久压倒核心经营安排；资源奖励不能瞬间跳过主要成长。用实际经济模型验证，不写统一适用于所有游戏的倍数。

## 接入与状态

开始广告相关开发前读取当前 `maker://ads-integration-guide`。确认目标项目、配置与前置条件后再按指南接入。

处理不可用、加载、播放、关闭、未完成、完成、错误、重复或迟到回调。奖励只在规定的成功条件下发一次；取消不伪装成完成，失败不扣成本。页面关闭后回调要有明确归属。

## 验收

模拟可检查状态机与重复回调；本地预览可检查入口和提示。真实设备需检查实际播放、完成判定、返回恢复与奖励到账，平台真实数据才能说明展示和收入。

记录广告请求、展示、完成、奖励与收入的口径，遵循平台实际能力；不要把模拟点击次数当广告展示，更不能当收入。
