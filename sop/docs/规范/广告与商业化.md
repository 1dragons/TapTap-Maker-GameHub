# 广告与商业化实战规范（OPT 模板 × 口碑红线）

游戏可以无广告。决定采用激励广告变现时，核心原则是：**用广告解决玩家当下真实的效率/资源痛点，让玩家看完觉得“赚了”，而不是被卡死后被迫看广告。**

## 1. 经过线上验证的高效低打扰入口（OPT 实战模板）

相比把广告藏在深层二级菜单无人问津，或弹出强制插屏惹怒玩家，以下结构在多款经营/模拟小游戏中兼顾了高转化与高评分：

| 策略 | 适用场景 | 设计要点 |
| :--- | :--- | :--- |
| **主 HUD 首曝 + 痛点胶囊** | 核心局内循环中 | 在主视野边缘放置轻量化、不遮操作的限时增益胶囊（如短时多倍收益/效率提升），玩家自然看见即可自主点击，避免藏进三级页面。 |
| **缺钱救场 & 动态补贴** | 玩家差一点钱买关键设施/升级时 | 当余额不足且差额处于合理区间时，在购买失败反馈处就地提供“看 1 次广告补足差额 / 领动态补贴”（补贴额随当前阶段动态缩放，避免后期鸡肋、前期崩盘）。 |
| **限时折扣券（如 8 折券）** | 中后期大额扩建/升级前 | 降低单次大目标的心理门槛，让玩家产生“省了一大笔”的爽感。 |
| **序章低门槛体验爽点道具** | 新手期/序章完成节点 | 允许玩家通过 **1 次**广告提前获得显著改善手感的实用工具或便利能力（如高效工具/自动帮手体验），迅速建立广告正向认知。 |
| **合理免广 / 每日上限保护** | 频繁使用或老玩家留存 | 提供明确可预期的每日免费/免广次数或合理冷却，保护核心游玩流畅度。 |

## 2. 口碑红线（严防 TapTap 1★ 差评风暴）

以下行为在真实线上反馈中被反复证明会直接引爆 1★ 差评与留存断崖，**一律禁止**：
- **严禁高倍重复逼看**：严禁出现单一关键目标/升级在正常玩法卡死的情况下需要连续观看十几次甚至几十次视频才能通过的设计。
- **严禁虚假/误触诱导**：不得将广告按钮伪装成普通“领取 / 继续 / 关闭”按钮，不得在高频连点位置延迟弹出广告入口诱导误点。
- **严禁打断首分钟体验**：开局首轮核心操作完成前不主动弹窗推广告。
- **保留纯自然推进路径**：不看任何广告也必须能顺畅体验全部核心玩法，广告只缩短等待或放大爽点，不锁死主线。

## 3. 奖励数值平衡核查

- 每个广告位必须写明：**触发情景、玩家痛点、奖励值、折合正常游玩时间、早中后期动态缩放公式、冷却/次数上限**。
- 测算是否存在刷奖励、无限叠加或单次奖励直接跳过整段成长的漏洞。
- 复活/救场不能让失败成本彻底归零；加速不能永久压倒核心经营策略。

## 4. 技术接入、埋点与平台配置核对

1. **先读最新指南**：接入或修改广告逻辑前，必须读取 `maker://ads-integration-guide` 与项目内 `engine-docs/recipes/sdk.md`。
2. **状态机与防重入**：完整处理不可用、加载中、播放、提前关闭、未完成、完成、失败、迟到与重复回调。
   - **仅在 `result.success == true` 时单次发奖**；
   - 取消或失败不伪装成功、不扣玩家原有资源、不卡死界面；
   - **返回恢复**：广告结束返回游戏时触发 `dt` 钳制与音频上下文恢复（避免返回后静音或计时跳变）。
3. **广告诊断埋点**：为每个主要广告位埋好「入口曝光 → 点击请求 → 播放完成 → 奖励发放」漏斗事件，便于上线后用 `game-diagnosis` 精准排查是“没人看见”、“没人想点”还是“播放填充失败”。
4. **发版前云端核对**：发布前通过 `taptap-maker-qa` 调用 `get_ad_config` 与本地 `.project/settings.json` 的 `@runtime.ad` 逐项比对（仅忽略 `synced_at`），防止测试广告位 ID 或错位配置带上线。

## 5. 验收证据区分

本地模拟回调只能证明状态机与单次发奖逻辑正确；**绝不能**将本地模拟写成“真实广告通过”或“广告收入已验证”。真机环境须单独核查播放唤起、返回音频恢复、奖励到账与平台真实展示数据。
