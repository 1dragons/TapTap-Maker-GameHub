# TapTap Maker 开发规范（UrhoX + Lua 生产级标准）

## 1. 开始工作与环境核对

在目标游戏目录优先读取 `maker://status`，不可用时调用 `maker_status_lite(target_dir="<项目绝对路径>")`；后续所有工具统一透传明确的 `target_dir`，绝不猜测项目目录，也绝不借用其他游戏的 `.maker-mcp/config.json` 或广告配置。

按状态输出给出的当前发行版指引文档路径与命令工作，不把过期 CLI 命令硬编码成永久习惯。SOP 资料库本身不是游戏项目，严禁将其初始化为 Maker 项目。

## 2. Maker 精灵功能边界

本 SOP 不包含 Maker 精灵生成流程，也不调用或反复尝试 Maker 的精灵生成能力。若工具提示“当前环境尚未支持精灵生成”，立即停止该调用，说明限制并等待用户指定替代工具或资源方案，不把普通静态生图冒充精灵序列帧。

## 3. 查文档的时机

| 工作内容 | 当前入口 |
| :--- | :--- |
| 开始、恢复、环境或绑定不明 | `maker://status` 与返回指引 |
| 设计稿还原、切图、UI.json 拼装与更新 | status 提供的 `maker-ui-workflow` |
| Bbox 预排或 `uiAtlasPrelayout` | `maker-ui-bbox-workflow`，保留参考链 |
| Lua UI 提取与 JSON 检查 | `lua-ui-to-json` |
| 资源元数据与 UUID | 官方 `generate_resource_meta` 工具（严禁手写或编造 UUID） |
| 广告与 SDK 集成 | `maker://ads-integration-guide` 与项目内 `engine-docs/recipes/sdk.md` |
| 本地预览与官方校验 | 当前发行版 `taptap-maker-local`（`run-lua-validate` / `preview validate`） |
| 构建与上传 | 必须完成 `taptap-maker-qa` 并获用户**明确授权**后再调用 |

## 4. UrhoX + Lua 生产级避坑铁律（高频实战总结）

以下条目均来自多款已上线小游戏的真实线上事故，**写功能第一天即应前置落实**：

1. **主循环 `dt` 上限钳制**：
   - 所有 `Update(dt)`、倒计时、经济产出、角色移动与物理步进入口必须强制钳制 `dt = math.min(dt, 0.05)`（或项目合理上限如 `0.1`），防止切后台、接电话或看完激励广告返回时 `dt` 飙升导致角色瞬移、物理穿模或订单倒计时瞬间归零。
2. **激励广告返回音频上下文重建**：
   - 移动端播放激励视频广告切回游戏后，系统音频焦点可能丢失导致 BGM/SFX 静默。在广告关闭回调与应用恢复前台回调中，必须触发音频上下文恢复/重建检查并恢复当前场景 BGM。
3. **3D / 动作类多指触控隔离**：
   - 移动端「左手虚拟摇杆 + 右手滑动镜头/交互」必须严格按 `touchId` 绑定并隔离手指归属，禁止把摇杆手指坐标误算成镜头旋转增量；切场景、弹弹窗或失去焦点时立即清空残余 `touchId` 与摇杆输入，防止视角抽搐或角色一直自动走动。
4. **3D 交互触发器优先级与防抢占**：
   - 3D 场景内多个交互点相邻时，必须规划清晰触发半径与**显式优先级**：高频日常核心动作（如前台接待、操作台、拾取）优先级高于一次性扩展牌、转让牌或低频功能入口，避免玩家走近核心点却被旁边的扩展弹窗抢占。
5. **UrhoX 引擎能力边界与回滚保护**：
   - 避免使用引擎不支持的几何变换接口（如不受支持的 `ProceduralGeometry` 变换），所有动态创建/改造场景对象做好空值检查与异常回滚（`Create` 失败不残留半成品节点导致死锁）。
   - 3D 移动场景做好材质/着色器预热、移动端画质档与帧率控制（目标稳定流畅 60FPS），检查走动遮挡淡出时不会引发场景阴影明暗跳变。
6. **异步回调防重入与页面销毁保护**：
   - 广告、云存档、排行榜、网络请求与计时回调必须防连点重入，并在回调触发时检查目标节点/弹窗是否仍然有效，避免迟到回调操作已销毁对象报错。
7. **生产代码与资源清洁**：
   - 发版前生产 Lua 代码 **LSP 诊断警告清零**；及时清理废弃 3D 模型、未引用大图与孤立 `.meta` 文件。
   - 所有跨文件资源路径严格保持**大小写完全一致**（Windows 本地不敏感但移动端/真机严格区分大小写，极易产生隐形 404）。
8. **仓库卫生与 `.gitignore` 隔离**：
   - QA 报告、诊断 HTML、验收视频、设计原稿、`docs/` 过程文档与本地测试 `save.json` 不得进入运行时资源目录，须在 `.gitignore` 中排除，避免膨胀游戏包体或造成构建状态误判。

## 5. AI 编程协作防乱改代码硬纪律

无论使用 Antigravity、Codex、Cursor 还是其他 AI 助手协作开发，均须严守以下工程纪律：

1. **改前必读上下文与调用链**：修改任何模块前先通读该文件及上下游调用关系，严禁凭记忆猜引擎 API 或在没看全文件时盲目重写整个大脚本。
2. **最小必要改动，严禁顺手“乱重构”**：修一个 Bug 或加一个功能时，严禁顺手改名已稳定的存档字段、调整无关 UI 布局、删除看似“没用”但由配置/事件反射调用的函数。
3. **直面根因，严禁伪装修复**：遇到报错、性能卡顿或兼容问题先定位真因；严禁通过“放宽风控、删掉校验、清空玩家存档、写死假数据”掩盖缺陷。
4. **守住用户现场与授权红线**：严禁执行 `git reset --hard`、`git clean -fd` 或覆写正式存档；严禁未经明确授权自动调用构建上传工具或推送远端代码。
5. **版本号三处一致**：发版改版本号时同步核对脚本常量（如 `GAME_VERSION`）、Maker 工程配置与最新 Git 提交说明，避免线上排查时口径错乱。
