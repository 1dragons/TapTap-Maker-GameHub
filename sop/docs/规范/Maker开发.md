# TapTap Maker 开发规范

## 开始工作

在目标游戏目录读取 `maker://status`，不可用时用 `maker_status_lite`；明确 target_dir，避免多目录误绑定。按状态给出的当前文档路径和 next_action 工作，不把过期命令硬编码成永久规范。

本 SOP 资料目录不绑定游戏项目。样例生成需要独立项目时，说明需要的绑定条件并按用户选择处理，不复制别的游戏 `.maker-mcp/config.json`，不改用户级 cwd，不用构建上传初始化资料库。

## Maker 精灵功能边界

本 SOP 不包含精灵生成流程，也不调用或尝试 Maker 的精灵生成能力。若 Maker 提示“当前环境尚未支持精灵生成”，立即停止该调用，不重复尝试、不换目标目录碰运气，也不把普通图片生成说成精灵生成。记录为当前环境不支持；如项目仍需要动作素材，先说明限制并等待用户指定可用工具或替代方案。

## 查文档的时机

| 工作 | 当前入口 |
|---|---|
| 开始、恢复、环境或绑定不明 | Maker status 与返回指引 |
| 设计稿还原、切图、UI.json 拼装与更新 | status 提供的 maker-ui-workflow |
| Bbox 预排或 uiAtlasPrelayout | maker-ui-bbox-workflow，保留参考链 |
| Lua UI 提取与 JSON 检查 | lua-ui-to-json |
| 资源元数据 | 官方 generate_resource_meta 工具，按当前输入要求 |
| 广告相关 | maker://ads-integration-guide，再按实际前置条件读取配置 |
| 本地预览 | 当前发行版的本地 preview 文档与明确 target-dir |
| 构建上传 | status 与用户明确授权后再调用当前构建工具 |

## 实现约定

优先复用既有组件、布局、事件和数据模型。修改之前检查现有工作与调用关系；大型新依赖需要实际收益，不能为单个页面换框架。保留用户未提交内容，不执行破坏性清理。

业务规则、状态和视图职责清楚即可，不为小项目过度抽象。列表、频繁刷新与计时避免不必要的重建。异步回调考虑重复、晚到、失败和页面已关闭的情况。

存档字段新增定义默认与旧版本读取行为；迁移先验证隔离数据，再影响正式存档。云存档、排行榜、广告等按真实 SDK 行为实现，模拟回调只作局部证据。

## UI 与资源

按官方 UI 工作流处理可编辑结构与资源，保留现有图层和关系；不要为一个按钮调整重做所有设计稿。资源导入检查引用、元数据和字体格式。生成 UUID 交给官方工具。

先测试一组资源的实际显示与加载，再批量引入。参考源码、字体全集和生成原稿不自动打包进游戏；只导入使用部分，并保留来源记录。

## 本地预览与性能

用户允许本地预览及自动重启。记录预览目录与当前版本，检查启动、触控模拟、长文本、资源状态和主路径。停掉的会话只有在本次任务需要且用户授权范围内恢复，不为无关工作唤醒项目。

性能先复现与测量：设备或预览环境、冷启动或热启动、操作步骤、样本条件。局部修改做针对性测量；比较前后使用可比条件，不拿不同资源、存档和加载路径作基线。

## 故障与完成

区分项目错误、绑定缺失、业务前置条件与 MCP 基础设施错误。按当前工具指引诊断；不升级未知包、不改全局配置来掩盖问题。请求已发出但状态不明时先核实，不能直接重复生成或上传。

交付说明实际改动、实际运行的检查、证据级别和缺口。构建成功、二维码生成或预览刷新均不代表真实广告、云存档、排名、收入和平台验收通过。
