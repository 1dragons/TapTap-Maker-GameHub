# 界面与交互规范

## 先定义页面目的

设计每个页面前读项目玩法、视觉基准和已有组件。填写 [单界面设计表](../模板/单界面设计表.md)：玩家来做什么、先看什么、主动作、返回路径、状态、反馈、资源、适配与验收。不要把原型期的临时按钮堆砌成正式 UI。

竖屏以游戏场景与关键操作为中心。顶部用于稳定概况，局内关键目标靠近相关对象；底部主操作须避开系统手势区域。具体位置以操作任务和预览决定，不机械套固定三栏。

### 截图研究转为布局方案

对于 TapTap Maker 的手机经营/模拟游戏，竖屏页面可先拆解优秀同类作品的结构方法：主体区域展示地图、店面或当前经营对象；顶部只保留跨页面需要的时间、货币、状态和进度；卡片把一个对象的资料、结果与操作放在一起；固定底栏承载平级主页面；当前页面的主要操作单独突出。不要默认照抄固定项数底栏、参考配色或页面数量，先依本项目循环决定导航和信息。

每张主要页面草图先标注阅读顺序：题材/对象 → 当前状态与目标 → 可选动作 → 结果预期。优先把对象和决策放在同一视区；若操作按钮需要玩家记住另一页的数据，应增加就地摘要或跳转回看。使用卡片时明确卡片之间的分组关系，避免把所有指标都放成同权重白色圆角框。页面里的大额数字、时间、角色状态与升级幅度使用字重、位置和颜色建立稳定区分，并保持足够对比度。

动作或像素项目重点保证战斗区域优先，生命/经验/地图/技能采用固定锚点，选择面板将浏览、详情与确认区分开。跨项目只迁移信息层级，HUD 坐标、技能槽数量和边框色彩须根据本项目操作与画面重新设定。

## 共用规则

- 每个层级有明确的主要动作与关闭方式，避免所有按钮同色同权重。颜色、形状、文字共同表达含义。
- 用可读真实文字和统一图标；不把 emoji 作为未经设计的正式图标系统。
- 重要触控目标可先以约 44–48 个逻辑单位的量级探索，结合 Maker 的坐标缩放、设备大小和实际操作校准；这不是直接填入引擎像素的硬规则。
- 保留安全区与触控间距，验证窄屏、长屏、刘海与手势区域；横屏项目重新安排主次，不把竖屏简单缩放。
- 弹窗防穿透、关闭明确；连续点击、打开中关闭、切页回来要有确定结果。异步操作避免重复提交。
- 文本允许合理换行，重要信息不能只靠省略号。大数字、倒计时、长商品名和空列表必须预排。
- 反馈尽量紧贴被操作对象，动效允许中断或合并，不用长动画阻断高频操作。
- 加载、空、禁用、成功、失败是不同状态；禁用要解释原因，失败要给恢复路径。

## 页面设计目录

下列为选用模块，不要求每个项目全部制作。每行的反馈均继承项目声音规范，静音时视觉仍能表达结果。

| 页面 | 目的与信息顺序 | 布局与操作 | 必须考虑的状态 | 动效、声音与验收重点 |
|---|---|---|---|---|
| 启动与加载 | 识别游戏、说明当前等待 | 品牌适量；进度或阶段说明清晰，必要时重试 | 初次、缓存、网络或资源失败、超时 | 不伪造进度；不循环轰炸提示音；验证小屏与错误恢复 |
| 主菜单 | 理解题材并开始或继续 | 场景表达身份；主动作突出，设置次要 | 新游戏、已有存档、恢复失败、版本信息 | 开始有轻反馈；长标题不挤压按钮，删除存档需防误触 |
| 局内 HUD | 看清目标、资源、压力和场景 | 高频信息靠近行动，低频系统收起 | 常态、资源变化、紧急、暂停、遮挡 | 数字变化与对象反馈同步，紧急提示不能只靠闪烁或声音 |
| 任务与订单 | 比较需求并决定接取或执行 | 摘要展示回报、成本、期限；详情渐进展开 | 无任务、可接、执行中、完成、超时、容量满 | 状态变化可定位；计时和长名称不重叠；连续接单防重复 |
| 设施与升级 | 判断升级价值和成本 | 当前效果→变化→价格→升级操作 | 可升级、余额不足、条件不足、升级中、满级 | 展示具体改善；结果落到场景对象；不能购买后才发现条件 |
| 商店 | 比较并购买符合需求的商品 | 余额稳定，效果与价格相邻，购买入口明确 | 可买、缺钱、已拥有、未解锁、售罄、失败 | 反馈显示获得什么与余额变化；防重复扣费，长价格可读 |
| 背包 | 找到物品并理解用途 | 分类、数量、详情、使用对象 | 空、不可用、数量不足、使用中、已消耗 | 使用结果能看到，数量与效果一致；关闭不重复使用 |
| 经营概况或公司 | 理解当前经营与下一步 | 关键指标优先，设施与人员等分组展开 | 未开放、有数据、无数据、条件未满足 | 重点体现经营对象，避免满屏后台统计卡片；小屏不拥挤 |
| 结算 | 理解本轮结果和下一步 | 结果→贡献与原因→奖励→继续或重试 | 成功、失败、部分达成、额外奖励可用或失败 | 展示可跳过的计分过程；奖励只能发一次；广告按钮与基础领取区分 |
| 设置 | 方便调整并安全退出 | 音乐、音效、必要选项与返回 | 开关、滑动中、保存失败、恢复默认 | 调整即时可感知，切页后保持；静音不能阻断操作反馈 |
| 存档与恢复 | 说明保存状态和冲突选择 | 本地与云端时间、来源、选择后果 | 正常、保存中、离线、失败、冲突、坏数据 | 不静默覆盖较新或未知存档；失败可恢复，正式存档隔离测试 |
| 排行榜 | 理解排名与自身位置 | 指标口径、范围、本人、榜单与刷新 | 加载、空、未授权、离线、服务失败 | 不编造玩家或排名；防频繁重复请求；长昵称可读 |
| 广告入口与奖励 | 理解自愿行为与实际回报 | 明示观看与奖励，保留正常玩法路径 | 可用、请求中、播放、未完成、成功、不可用 | 不诱导误触；失败不扣奖励成本；重复回调不重复领奖 |
| 异常与确认提示 | 理解影响并恢复操作 | 简短原因、可行动选项、关闭或返回 | 可恢复、需等待、需重新进入、危险操作 | 不用技术堆栈当玩家文案；提示可读、不连续叠弹窗 |

## 页面制作顺序

页面目的→信息结构与操作状态→图像生成整页设计稿→版本选择与视觉样板确认→提取颜色/字体/布局规格→Maker 组件和资源按图实现→动效声音→实际预览与设计图并排对照→修订及适配。所有正式页面先出设计稿；先确定主页面风格，再逐页扩展。具体按[UI 先出图，再按图实现](../流程/UI设计稿到实现.md)执行。

Maker 的 UI 设计稿、切图、UI.json 拼装及更新，先读当前状态提供的 `maker-ui-workflow`。已有界面改动保留原有关系与资源，不因小调整重跑整套图片生成。

## 必查场景

最长文本、最大合理数值、空列表、未解锁、资源不足、按钮连点、动画中关闭、切到后台再返回、弹窗叠加、窄屏与长屏。共享组件修改扩查实际使用页面，其余局部改动只验证相关路径。
