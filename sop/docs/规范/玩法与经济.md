# 玩法与经济规范

## 核心循环

写出玩家反复执行的动作、可选择的策略、反馈、压力与下一轮变化。区分行动循环、单局目标和长期成长。经营游戏的资源增长需要对应可感知变化，例如操作空间、生产安排或订单组合，避免只有更大的数字。

首分钟优先让玩家完成一次有效行动。教学贴近当前操作，不一次解释全部系统；后续逐步引入选择。开局时间指标由项目和试玩决定，不套统一的“黄金秒数”。

## 有效选择与难度

- 选择至少有可理解的代价，例如更高收益与更长占用、更快交付与较低利润；检查是否存在始终最优且无需思考的选项。
- 难度分解为信息量、操作速度、资源约束和失败成本。逐次改变，避免同时陡增。
- 等待应能观察进展、安排其他事或作出选择。无法解释作用的等待优先缩短。
- 失败要解释原因、保留合理成果、提供清楚的重试或调整路径。
- 内容变化优先改变决策，再增加数量；同一操作换皮十次不算十种玩法。

## 经济设计

建立资源表：来源、用途、产出频率、消耗频率、上限、离线规则和存档位置。以实际游戏时间推算一轮、一个成长阶段和一次主要升级的收入与支出，列出计算假设。

| 检查 | 要回答的问题 |
|---|---|
| 基础可持续 | 不看广告时是否仍能推进，是否存在无意的资源死锁 |
| 成长速度 | 新能力出现前是否有足够玩法变化，是否过早耗尽内容 |
| 奖励价值 | 奖励折合多少正常操作或时间，是否跳过主要成长 |
| 消耗意义 | 支出是否带来新选择或清晰改善，而非反复扣费 |
| 通胀与囤积 | 后期资源是否失去用途，是否产生无上限加速 |
| 退出恢复 | 离线结算、时间变化、重复领奖是否定义明确 |

记录基准路径、低效率路径和熟练路径，不只测最理想玩法。广告与额外奖励单列，避免把广告后的收入误当基础平衡。

## 数值修改交付

说明触发问题、改动前后示例、受影响成长阶段、正常与异常输入、存档兼容。用小表或可复算公式说明，不必为简单调整开发新的数值工具。验证收益只是游戏内经济证据，不等于真实商业收入。
