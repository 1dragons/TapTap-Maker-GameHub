# 美术与资源规范

## 每个项目自己的视觉方向

先确定题材、情绪、玩家年龄与可接受的制作成本，再选择画风。参考库不预设所有经营游戏都用相同卡通风。

风格说明必须包含：参考来源与借鉴点、主辅色、明暗范围、形状语言、描边规则、视角、角色与物件比例、材质、光向、层级、动效与禁止项。给出实际场景、角色和图标对照，避免只写“高级、精致、治愈”。

### 从实机截图借鉴界面的视觉语法

拆解同题材或跨题材实机截图时，重点提炼“场景说明题材、状态位置稳定、卡片围绕对象聚合信息、主动作有明显权重、同一项目内组件一致”的信息层级方法。必须在项目里重新设计颜色、字形、图标、卡片比例和画面素材；不要把参考截图直接当 UI 图或把其他游戏的角色图片用于资产。

每个视觉样板至少保留：来源截图与页面用途、参考中注意到的布局原则、本项目线框、色板与字体/字重表，以及实际 Maker 预览截图。按题材选择美术表现：写实地图、人物立绘、手绘场景或扁平图形都只是候选，需形成同一项目自己的规则。风格一致不等于所有项目长得一样。

像素、深海探索或动作类界面重点把控高对比轮廓、深色场景上的清晰强调色、固定 HUD 锚点和选择/详情面板结构。正式资源必须为项目重新绘制或生成，像素风保持规则网格与干净边缘，不添加随机噪点。

## 来源决策

1. 已有项目资源和 Maker 组件符合方向时优先复用。
2. 成熟 UI 与源码用于研究结构与实现，不直接替代项目审美判断。
3. 项目独特场景、角色和主题物件优先通过 Maker 生成并筛选。
4. 外部免费商用素材仅作精选补充，逐项检查许可与风格兼容。
5. 付费素材只提供候选与成本，未经明确决定不购买。

## 生成流程

整页 UI 视觉设计先按[UI 设计稿到实现](../流程/UI设计稿到实现.md)出图，选定版本后提取色值、字体和布局规格，按图还原实际界面。设计稿中可用文字表达排版，检查并校正中文；正式游戏文字仍由真实字体组件显示。场景、角色、图标等单项美术资产遵循下列生成与入库步骤。

需求表→明确风格与规格→小样→检查→确认样板→带参考生成同批资产→引擎实际检查→入库。

生成要求包含用途、主体、视角、构图、色彩、描边、光向、背景、目标尺寸和排除项。所有图片明确无噪点、无颗粒、无不必要纹理；不要求模型生成正式 UI 字、商标或水印。

角色、场景和图标使用共同风格锚点及合法参考图。保留每次请求、返回位置、筛选原因与修改记录。调用设置使用用户选择或工具默认模型，不随意指定后端。超时先检查任务与输出，不盲目重试。

透明切图检查背景是否真正透明、边缘是否有白边或暗边、主体是否完整；实际叠到明暗底色检查。尺寸和缩放服务于最终小屏阅读，不以分辨率越大越好。

## 资源需求与入库

每项写明资源 ID、用途、所属页面或对象、源文件与导出文件、尺寸、透明需求、锚点、动效帧或切图关系、来源、许可、验证状态。动态显示区域与文字分离；不把所有按钮、文字和状态压成不可变背景。

命名可读且稳定，按场景、角色、UI、图标、音频、字体分组。Maker 元数据必须使用官方生成工具，不编造 UUID。只导入实际使用资源，不把整套参考库复制进游戏。

## 验收

检查风格一致、轮廓、透视、比例、光向、透明边缘、缩小辨认、视觉层级、包体与加载。资源级检查不等于 Maker 导入或真机通过。授权和生成条款未核实时标记待确认，不将“生成”写成版权无条件保证。
