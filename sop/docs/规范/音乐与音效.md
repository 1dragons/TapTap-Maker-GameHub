# 音乐与音效规范

## 从体验出发

先填场景情绪表：进入、准备、操作、压力、成功、失败、暂停各自需要什么感受。不是每个状态都要一首音乐；可以用同一主题、环境声或留白控制疲劳。

音乐要求包含情绪、节奏、乐器、强度、是否有人声、循环与切换方式、需要避开的风格。经营游戏高频操作时避免音乐与奖励音效争抢注意力。默认不能把纯音乐意图寄托于模型猜测，工具支持时明确设置 instrumental。

## 事件音效表

| 事件 | 声音目的 | 行为约束 |
|---|---|---|
| 点击 | 确认轻操作 | 短、轻；高频点击合并或限频，不每次都响亮播放 |
| 交易成功 | 确认获得与消耗已生效 | 与视觉结果同步，避免重复事件叠加 |
| 订单完成 | 形成阶段满足感 | 比普通点击更有层次，但不能长时间阻断下一单 |
| 错误或资源不足 | 提醒操作未发生 | 温和且有视觉解释，重复误点不刺耳 |
| 紧急状态 | 提高注意力 | 限制频率，静音时仍有清晰视觉提示 |
| 页面切换 | 帮助空间与状态理解 | 只有有意义时使用，不给每层面板都堆声音 |

## 生成与选择

Maker 音乐、音效工具分别调用，保留请求、任务 ID、返回和选择原因。首批先验证一段主题音乐与几个关键事件，再扩展。网络中断或超时不能证明失败，先查状态与输出，避免重复生成。

生成结果可能自带开头、尾奏或多个变体。试听完整结果，确定选段与切换，不把“有 loop 开关”当无缝循环证据。声音样本来自外部时独立检查许可，代码许可不包含音乐版权。

## 整合规则

音乐与音效分别有音量、静音和持久化设置；项目可增加总音量，但避免重复控制混乱。切场景淡出淡入或在合适节点切换；后台暂停和返回不能叠播。重要事件按优先级控制同时发声数。

避免为追求热闹压大所有声音。先让常态舒适，再比较订单完成和紧急提示的相对强度。音量与限频参数在实际混音中确定并记录，不套未经试听的固定数值。

## 验收与证据

资源级检查：能播放、时长、声道、峰值削波风险、开始与结束、是否误带人声、循环接缝试听。音乐循环至少实际听一次衔接，不凭波形判断。

游戏内检查：点击与视觉同步、高频事件、重复订单、切页、静音、重新进入、后台返回。使用普通外放与耳机各试听后记录设备；没有设备时明确未验收。浏览器单文件试听不能证明游戏内混音和平台播放通过。
