# 从参考源码到 Maker 设计

本页基于已下载的固定版本源码与说明进行只读研究，没有运行 Unity 项目或安装第三方 Skill。研究结论用于设计方法，不构成已验证的 Maker 实现。

## Balatro-Feel：让操作与视觉互相配合

版本：aa2c8acd0202126c788c0ff081692c9b69762961。源码归档与选读文件在 `library/sources/Balatro-Feel`。

`Card.cs` 处理按下、抬起、拖动和选择状态，向视觉层发出事件。`CardVisual.cs` 监听这些事件，分别处理缩放、轻微摆动、阴影位置、跟随与绘制层级。`HorizontalCardHolder.cs` 组织槽位、交换与拖动后的返回。

可以借鉴三点：操作对象的状态有明确归属；表现层响应事件；同一个动作通过大小、位置、阴影等多种轻反馈一起表达。不要误解成所有页面都需要摇晃和弹跳。

| 参考行为 | Maker 经营项目中的用途 | 移植时应调整 |
|---|---|---|
| 按下与抬起视觉不同 | 商品、订单和设施按钮确认输入 | 结合触屏取消与滑出，不让按下直接扣费 |
| 拖动时提高绘制层级 | 安排订单、拖动物件 | 限制可拖区域与遮挡，定义多指和打断行为 |
| 拖动结束返回槽位 | 未完成放置的恢复反馈 | 保存原状态，区分成功放置与取消 |
| 状态和视觉分离 | 业务结算不依赖动画播放完毕 | 允许合并或打断动画，防重复奖励 |

源码包含鼠标悬停、左右键和键盘相关逻辑，手机不能直接照搬。原工程使用 Unity、C# 与 DOTween，不是 Maker 可直接导入的插件。具体动画幅度与时长在触屏样板里决定，不把原值当普遍标准。

## UI UX Pro Max：借鉴设计判断过程

版本：9a3f14f7423037ccb8feeb4fee7482291b9c820e。保留原始源码归档、许可证、说明、上游截图，以及字体和 UX 数据的选读副本。

适合吸收的是先确定使用场景，再组合字体、配色、交互和检查清单的方式。网页标题字体配对不能直接证明中文手机游戏可读；鼠标悬停和键盘焦点也不能代替触屏反馈。

上游截图仅用于观察网站设计系统的展示方式。它不是经营游戏首页模板，不直接作为游戏资产。数据中的建议需逐条判断，不能安装后把整套规则强加给所有游戏。

## magictools：解决明确缺口

版本：7080961ac29fd112d2accd7b2dd475fb8f5914da。已下载索引原始版本和许可，未批量下载外链素材。

先确定需要解决的问题，再从相关类别找来源。例如需要切图工具、某类环境音或专业学习资料时进入对应条目。重新查看原作者当前说明、资源许可与引擎条件，不能凭索引标签直接认定可商用。

## 把研究变成项目交付

在项目参考分析中写：来源→观察到的具体方法→本游戏的用途→需要改变的部分→Maker 原型验证。参考不是用来证明“高级”，而是帮助做出一个可检查的设计决定。

## 跨题材实机视觉参考原则

按项目题材自主挑选高质量实机截图进行研究：经营与模拟类重点观察题材场景焦点、状态栏稳定性、对象卡片聚合与固定导航；动作或像素类重点观察战斗主区域留白、固定 HUD 锚点以及浏览/详情/确认的层级分离。跨题材借鉴时只迁移信息层级与读图方式，重新设计项目自己的素材和组件。
