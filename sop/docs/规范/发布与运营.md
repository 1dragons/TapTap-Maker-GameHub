# 发布与运营规范

## 发布物料

图标在小尺寸能辨认题材和主体，不把整幅游戏截图缩进去。名称可读且不误导。截图突出真实玩法、关键选择和反馈，避免只展示商店或堆文字。介绍说明玩家身份、核心行为、可感知特点与适用节奏，不写无法证实的宣传。

实际游戏画面与宣传保持一致；概念图若采用须明确用途，不伪装为已实现玩法。字体、音乐、图标与其他素材的授权记录随项目保存。

## 发布候选清单

- 目标方向、版本、包体、配置、存档版本和已知问题有记录。
- 首局与主要路径可运行，适用的网络与后台恢复已检查。
- 设备适配、真实广告、云存档、排行等分别记录结果与缺口。
- 隐私与平台资料按实际收集和 SDK 行为填写，不使用不匹配的通用声明。
- 用户确认发布候选；构建上传另有明确授权，记录授权范围。

## 执行动作

先按 Maker 当前状态与官方指南操作；不因工具提示“需要构建”就绕过用户同意。构建、上传、审核、正式发布是不同状态，逐项报告真实结果。

出现错误先定位是否代码、资源、环境或平台问题，再修复。对状态不明的请求查结果，避免重复提交。回退需考虑存档兼容，不以清空存档替代修复。

## 上线复盘

参考 [上线与迭代](../流程/上线与迭代.md)，先区分曝光、点击、启动、首局、留存与商业化。没有真实数据时明确缺口，不把产品没有流量一律归因于玩法。
