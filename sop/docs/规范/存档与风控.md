# 存档演进、防刷风控与数值安全规范

线上小游戏一旦积累了真实玩家，**丢档、升级崩溃和外挂刷榜**是最直接摧毁评分与留存的致命事故。本规范提炼自多款高留存线上项目的实战经验，作为正式制作与发布前 QA 的硬性红线。

## 1. 老存档跨版本直升（零崩溃、零丢进度）

1. **强制显式版本号**：
   - 存档根对象必须持久化 `saveVersion`（整数递增，如 `1, 2, 3...`），严禁仅靠猜测字段存在与否判断版本。
2. **渐进迁移链（`Gen0 → GenN`）**：
   - 加载存档时统一经过 `MigrateSave(raw)` 管道，按 `v1 → v2 → v3 ...` 顺序逐代补齐新字段、转换结构并保留老玩家已获得的资产、建筑、员工、解锁状态与成就。
   - **禁止破坏性改名**：若必须重构旧字段名，迁移函数必须读取旧键并安全映射到新键，同时为所有嵌套表提供防 `nil` 默认值兜底。
3. **隔离老档回归验证**：
   - 每次涉及存档结构变更的大/中版本，发布前必须用 Git 历史比对上一上线版本的存档 schema，并用**隔离的旧版样例存档**验证完整加载、首帧渲染与二次保存；严禁操作玩家或开发者本地正式存档目录。
   - 严禁以“提示玩家删档重来”或回退清档替代迁移逻辑。

## 2. 多槽位、防误删与长周期老档瘦身

1. **多槽位与撤销备份（Undo Backup）**：
   - 经营模拟、多周目或长线养成项目，推荐提供 **多存档槽位（如 3 槽位）** 与明确的重置/删档能力（满足玩家开新档诉求）。
   - 删除或覆盖存档前，必须设置二次确认并在本地保留最近一份 **撤销备份（Undo Backup）**，避免误触导致不可逆丢档。
2. **长周期老档瘦身（防膨胀卡顿与云存档超限）**：
   - 严禁把无限增长的流水日志、历史订单明细、已失效临时事件全部无上限写入主存档。
   - 对历史记录数组设置硬上限（如仅保留最近 N 条用于展示，长期统计仅存聚合计数），在迁移函数里顺手对老玩家已膨胀的数组执行一次安全裁剪瘦身。
3. **云存档冲突保护**：
   - 明确记录本地与云端存档的保存时间与关键进度摘要；发生冲突时给出清晰对比与选择，绝不静默用空档或旧档覆盖玩家高进度存档。
   - 写入采用安全覆盖策略，避免中途异常导致存档半写损坏。

## 3. 排行榜防刷与风控封禁体系

凡是接入云端排行榜的项目，上线前必须同步具备基础风控能力：

1. **合法性校验与异常拦截**：
   - 上报前在逻辑层校验数值合法性（拒绝 `NaN`、`inf`、负数、违背游戏物理上限的瞬间暴涨）。
   - 对单周期异常增速、非法篡改痕迹建立风控标记与自动封禁/屏蔽上榜机制，防止外挂霸榜挫伤正常玩家积极性。
2. **TapTap 昵称与展示兼容**：
   - 榜单显示必须对超长昵称做安全截断（支持 UTF-8 多字节中文，严禁按字节硬切导致乱码），兼容空昵称、特殊符号与表情字符。
   - 涉及感恩榜/昵称匹配功能时做好去空格与兼容匹配。
3. **大额数值安全与溢出防护**：
   - 经营类后期累计收入、资产容易突破 32 位整型上限甚至触碰平台榜单整型边界：早期即规划好榜单存储单位（例如直接按「元」或「千元/万元」统一口径，不混用单位），UI 层做好万/亿/兆格式化展示。

## 4. 发版前调试与作弊开关清零清单

构建上传前必须全仓检索并确认关闭以下开关（同时纳入 `taptap-maker-qa` 必查项）：
- GM 面板 / 修改器面板 / 无限金币测试按钮 / 跳关快捷键；
- 排行榜诊断标志（如 `diag` / `probe` / 强制刷榜调试模式）；
- 跳过广告直接发奖的本地调试开关；
- 高频刷屏 `print` / 性能探针日志。
